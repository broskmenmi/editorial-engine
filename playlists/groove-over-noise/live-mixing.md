# GROOVE OVER NOISE — Live-Mixing Doctrine

The live-mixing layer helps answer:

> What can I play next while preserving the GROOVE OVER NOISE identity and the current chapter?

It is separate from the canonical ordered-listening playlist.

## Non-interference

A live transition edge must never silently change:

- `ledger.md` or Spotify order;
- `journey-annotations.json`;
- ADD, REVISIT, or REJECT state;
- protected opener, handoffs, or ending;
- a frozen listener-feedback region.

A performance discovery may later become an editorial proposal, but it must enter the normal Scout → Evaluator → Sequencer → Auditor → Librarian process.

## Graph model

The performance layer is a directed graph.

- **Node:** one exact track identity.
- **Edge:** one possible source → destination transition.
- **Route:** a chapter-preserving path assembled from edges.
- **Canonical edge:** the corresponding adjacent pair in the Spotify ledger.
- **Alternative edge:** a live option that does not alter canonical order.

Several exits may leave one track. Direction matters.

## Edge evidence

Record when available:

- BPM and required tempo adjustment;
- key and harmonic relationship;
- phrase alignment;
- possible mix-out and mix-in regions;
- overlap duration;
- rhythmic and spectral density relation;
- vocal overlap risk;
- energy-trajectory relation;
- evidence provenance and confidence;
- listener report relevant to either track or transition.

Missing values stay unknown.

## Edge character

Label each proposed edge with one primary purpose:

- `CONTINUE` — preserve bodily and attentional continuity;
- `LIFT` — increase pressure without spending the summit;
- `RELEASE` — reduce pressure while retaining immersion;
- `RE-ENTER` — begin a new wave without sounding like a restart;
- `RESET` — intentional scene change, used sparingly;
- `EMERGENCY EXIT` — recover from a route that is not working.

These are editorial interpretations, not measurements.

## Compatibility standard

A live edge must pass both:

1. **Identity gate:** the destination belongs in GROOVE OVER NOISE.
2. **Transition gate:** the directional source → destination handoff is viable for the intended chapter and edge character.

Harmonic compatibility alone is insufficient. BPM compatibility alone is insufficient. DJOID or rekordbox suggestions are candidates, not approvals.

## Chapter preservation

Prefer alternatives that keep the current chapter legible.

- Arrival exits should not spend the summit.
- Partial releases should not return to zero.
- Re-entry should retain accumulated immersion.
- Summit alternatives should not create several competing main peaks.
- Decompression exits should not reopen the journey accidentally.
- Dissolution should close.

## Protected and frozen regions

Protected canonical pairs may be shown as preferred live edges. Alternatives through them require an explicit live-performance request.

Frozen regions remain unavailable for new editorial or performance routing until clarification is complete, unless the user explicitly requests a non-canonical practice-only analysis that cannot affect playlist state.

## Output for a live request

For each loaded or selected track, return a small ranked set of viable exits with:

- destination;
- edge character;
- measured and model-derived evidence;
- listener evidence;
- chapter effect;
- principal risk;
- confidence;
- source tool where applicable.

Do not present a single opaque “best next track.” Explain the tradeoff in plain language.

## Relationship to rekordbox and DJOID

rekordbox is useful for immediate deck-centred suggestions. DJOID is useful for library-wide similarity and multi-track context. Their exports may populate candidate edges under `audio-evidence.md`.

The GROOVE OVER NOISE doctrine remains responsible for identity, chapters, protected state, listener authority, and the distinction between canonical listening and live performance.
